Level 1 命令注入 OS Command Injection

学习用户输入进入系统命令时的后果：从"让服务器发一个请求"， 升级成"让服务器执行一条命令"。
Learn what happens when input reaches an OS command: from making the server send a request, to making it run a command.

难度 Difficulty：Intermediate 中级 目标 Goal：让沙箱里的 secret.txt 出现在输出里

{% endblock %} {% block lab_intro %}

实验说明 Description

这是一个"网络诊断"工具：你填一个主机名或 IP，后端执行：
ping {% if is_windows %}-n 1{% else %}-c 1{% endif %} <你的输入>

命令是字符串拼接出来的，而且交给了 shell 执行。 shell 的职责就是解释 &、|、; 这些"命令分隔符"。
The command is built by concatenation and executed through a shell. A shell's whole job is to interpret separators like &, | and ;.

通关判定：命令输出里出现了沙箱目录中 secret.txt 的内容（本关的 flag）即视为通关。 也就是说：你成功让服务器执行了一条不属于这个功能的命令。
Completion rule: the command output must contain the contents of secret.txt from the sandbox directory — that is, you made the server run a command this feature was never meant to run.

⚠️ 这一关真的会执行系统命令。为了限制爆炸半径，靶场做了三件事： 工作目录固定在 lab_sandbox/、执行超时 {{ timeout }} 秒、 输出截断 4000 字符。输入本身没有任何过滤 —— 过滤了就不是这个漏洞了。 请只在自己的机器上玩。
⚠️ This level really executes OS commands. To limit the blast radius the lab fixes the working directory to lab_sandbox/, caps execution at {{ timeout }}s and truncates output. Input is not filtered — filtering it would remove the vulnerability. Run it on your own machine only.

这就是命令注入的后果：输出的内容不再只由 ping 决定， 而是由你追加的那条命令决定。 在真实服务器上，这条命令可以读任意文件、下载并运行程序、连回攻击者的机器。
This is the consequence: the output is no longer decided by ping but by the command you appended. On a real server it could read any file, download and run a program, or call back to an attacker.

两个条件凑成了这个漏洞：字符串拼接把输入送进了命令行， shell=True 让 shell 去解释它。 少任何一个，都不构成命令注入。
Two conditions create this bug: string concatenation puts input on the command line, and shell=True lets a shell interpret it. Remove either one and the injection disappears.
