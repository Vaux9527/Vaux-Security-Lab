学习利用 SQL 注入绕过身份验证，以及为什么认证逻辑不应该写进 SQL。
Learn how SQL injection bypasses authentication, and why an authentication check should never live inside a SQL statement.

实验说明 Description

这是一个登录表单。后端代码故意把用户名和密码直接拼接进 SQL 语句， 并且把「能不能登录」这个判断整个写进了 SQL 的 WHERE 条件里：
WHERE username = '...' AND password = '...'

This is a login form. The backend intentionally concatenates the username and password into the SQL statement, and expresses the whole authentication decision as a SQL condition.

通关判定：登录语句返回了管理员账号 {{ target_user }} 的记录，并且你提交的账号密码 并不是数据库里的合法凭据——换句话说，你要证明自己是 绕过了密码，而不是知道密码。
Completion rule: the login statement must return the administrator account {{ target_user }}, and the credentials you submitted must not be a valid pair in the database. You have to bypass the password, not know it.

提示：直接输入 admin / admin123 是正常登录，不算通关。 本关要的是不靠密码进去。
Note: admin / admin123 is a normal login and does not count. This level requires getting in without the password.
